# 02 — Cross-Reference Checker & Static (Manually-Typed) Numbering Detector (Proof tab)

**Status:** ✅ v1 — two distinct features (A and B) under the Proof tab; both detect-and-flag.

This document specifies two related-but-distinct features that **must not be conflated**:

- **Feature A — Cross-Reference Checker** (`featureId: 'xref'`). Validates cross-references *in prose* ("see Clause 4.2", "paragraph 3 of Schedule 2") against an index of the document's actual numbered units. Classifies each as OK / Not Found / Ambiguous, and badges manually-typed (non-field) references as possibly stale.
- **Feature B — Static (Manually-Typed) Clause Numbering Detector** (`featureId: 'staticNumbering'`). Detects clause *numbers themselves* that are hand-typed rather than produced by Word's list engine, and flags them. Detect-and-flag only.

This feature **authors** the [Section Index Builder](../ARCHITECTURE.md#section-index-builder); the shared *interface* lives in ARCHITECTURE.md (consumed there by Interactive Lookup and Numbering). The **authoritative builder algorithm** is retained here (Clause 4) because Cross-Reference is its implementation owner.

> **CRITICAL CONCEPTUAL SEPARATION.** Feature A's "static-reference badge" (a *pointer* that is plain text rather than a REF field) and Feature B's "static numbering" finding (a *clause number* that is hand-typed) are **different findings about different objects** and **MUST NOT be conflated** in code, copy, or task-pane grouping. They share the word "static" by coincidence of English, not by domain. The `featureId` discriminator (Clause 5.4) enforces this at the data layer. See Clause 8.4.

## 1. Purpose & user value

### 1.1 Feature A — Cross-Reference Checker

Legal documents are dense webs of internal references. During heavy editing references silently rot: "see Clause 4.2" survives the deletion of clause 4.2. In SG/UK practice many references are **manually typed plain text** (not Word REF fields), so Word's own "update fields" does nothing for them.

- **Catch broken references** ("Not Found") before the document is executed or filed.
- **Catch ambiguous references** ("Clause 5" when only 5(a)/5(b) exist).
- **Badge manually-typed references** so the reviewer knows which pointers Word will *not* keep in sync.
- **One-click repair** via the Assign-source picker: pick the intended target, replace with correct static text.

### 1.2 Feature B — Static Numbering Detector

A clause whose "4.2" is typed by hand rather than generated by Word's list engine will not renumber when clauses are inserted/removed, breaks the automatic Table of Contents, and is invisible to `listString`-based tooling (including Feature A's index). It is a latent defect.

- **Surface every paragraph whose leading number is hand-typed**, low/medium severity, with jump-to-paragraph navigation, so the drafter can decide whether to convert it (manually — we do **not** convert).
- Improves the reliability of *every* feature that relies on the Section Index, because static numbering is the main reason the index can be incomplete.

## 2. Scope

### 2.1 In scope (v1) ✅

**Feature A:** build the Section Index for the body; regex-scan body prose for reference patterns (Clause / Schedule / paragraph-of-Schedule / Annex / Appendix / Part / Recital, plus compound and range forms — Clause 6); resolve each against the index and classify **OK / Not Found / Ambiguous**; **static-reference badge** (REF-field-backed or not); **Assign-source workflow** (v1 = static text replacement only); informational cross-document exhibit handling ("may be in a separate file") without resolution.

**Feature B:** per-paragraph static-vs-dynamic numbering detection via the three-layer heuristic (Clause 5.2); per-paragraph low/medium-severity Finding with jump-to navigation.

### 2.2 Explicitly cut ❌ (do not build in v1)

| Cut item | Reason |
| --- | --- |
| **True out-of-date / staleness detection** (reference points to a unit that *moved or changed meaning*) | Requires version history / a previous snapshot. Replaced by the static-reference badge (heuristic proxy). |
| **Live REF-field insertion** in Assign-source | v1 replaces with static text only. Deferred to v2 (seam present). |
| **Cross-document exhibit resolution** | Office JS cannot read sibling files. We flag "may be in a separate file"; never resolve. |
| **Feature B static→dynamic CONVERSION** | Too risky (OOXML list surgery). Feature B is **detect-and-flag only**. No conversion, no OOXML mutation. |

See [README.md](../README.md#feature-list) for the consolidated lists.

### 2.3 Glossary (read first)

| Term | Meaning here |
| --- | --- |
| **Numbered unit** | A division that can be cross-referenced: Clause, sub-clause, Schedule, paragraph-of-Schedule, Annex, Appendix, Part, Recital. |
| **Reference (Feature A)** | A *pointer in prose* to a numbered unit, e.g. the text "Clause 4.2". |
| **Numbering token (Feature B)** | The *leading number of a unit itself*, e.g. the "4.2" that begins clause 4.2's paragraph. |
| **`listString`** | The rendered auto-number from `paragraph.listItem.listString`, e.g. `"4.2.1"`, `"(b)"`. Load-bearing. |
| **Static** | Text that is a literal `<w:t>` run, not produced by the list engine or a field. |
| **REF field** | A Word `REF`/`PAGEREF` field — a live cross-reference. Detected via `paragraph.fields` (parse `field.code`). |

## 4. The Section Index builder (authoritative algorithm)

> The shared *interface* (`SectionIndexEntry`, `SectionIndex`) is published at [Section Index Builder](../ARCHITECTURE.md#section-index-builder). The implementation detail below is the authority. Built once per check run (invalidated on document change), from the Document Model's single pass — **no extra paragraph enumeration.**

### 4.1 Inputs

The ordered paragraph descriptors from the Document Model. Per paragraph the builder reads `listString`, `listItem.level`, `style`/`styleBuiltIn`, `text`, and a running **structural context stack** (4.3).

### 4.2 Output: `SectionIndex`

```ts
interface SectionIndexEntry {
  /** Canonical normalized key, e.g. "clause:4.2", "clause:5(b)",
   *  "schedule:2", "schedule:2/para:3", "recital:B", "annex:A", "part:II". */
  key: string;
  unitType: UnitType;              // 'clause' | 'schedule' | 'paragraph' | 'annex'
                                   // | 'appendix' | 'part' | 'recital'
  /** Display label as it should read in prose, e.g. "Clause 4.2",
   *  "paragraph 3 of Schedule 2", "Recital (B)". Drives Assign-source replacement text. */
  displayLabel: string;
  rawNumber: string;               // the rendered token, e.g. "4.2", "(b)", "B", "II"
  parentKey: string | null;        // e.g. "schedule:2" for a paragraph-of-schedule
  level: number;                   // list level (0-based) or derived depth
  paragraphId: string;             // stable id from Document Model
  range: Word.Range;               // lazy accessor; for navigation + REF target check
  isStaticNumbered: boolean;       // true if this unit's own number is hand-typed
                                   // (cross-populated from Feature B; see 5.2.4)
  bookmarkNames: string[];         // bookmarks anchored at/around this unit (for REF resolution)
}

interface SectionIndex {
  byKey: Map<string, SectionIndexEntry[]>;   // value is an array: >1 ⇒ ambiguous key
  ordered: SectionIndexEntry[];              // document order, for the picker
  has(key: string): boolean;
  resolve(key: string): SectionIndexEntry[]; // [] none, [x] unique, [x,y,...] ambiguous
}
```

`byKey` maps to an **array** deliberately: when two units normalise to the same key (a Schedule renumber left two "Schedule 2"s, or "5" is implied by both 5(a) and 5(b) with no standalone 5), the array length drives Ambiguous classification.

### 4.3 How keys are built (the core algorithm)

For each paragraph, in document order, maintain a **context stack** of the current Schedule/Annex/Appendix/Part/Recital region:

1. **Determine the unit type** from style + context:
   - If the style is a Schedule/Annex/Appendix/Part heading style (config list + heading-text regex fallback `^\s*(Schedule|Annex|Appendix|Part)\b`), it **opens a new structural region**; push it onto the context stack and pop any sibling region.
   - A Recital region is opened by a "Recitals"/"Background" heading or the first lettered `(A)` recital; recitals are lettered.
   - Otherwise the paragraph is a **clause** (in the body) or a **paragraph** (inside a Schedule/Annex/Appendix region — the SG/UK sub-unit name).
2. **Read the rendered number.** Prefer `listItem.listString`. If `listItem` is null (static numbering — Feature B), fall back to a leading-number regex on `text` so the unit is *still indexable* (with `isStaticNumbered = true`). Never silently drop a static unit; that would create false "Not Found"s.
3. **Normalise the number** (4.4) → `rawNumber`.
4. **Compose the key** from `unitType` + normalised number + parent context:
   - Body clause `4.2` → `clause:4.2`.
   - Sub-clause rendered `(b)` under clause 5 → `clause:5(b)` (concatenate ancestor clause numbers up the list-level chain, joining decimal parents with `.` and lettered/roman children with parenthesised suffixes, mirroring how the unit reads in prose).
   - `(b)` whose ancestors render `5` ⇒ `5(b)`; `(i)` whose ancestors render `5(b)` ⇒ `5(b)(i)`. Reconstructed by walking list levels, **not** string-guessing.
   - paragraph 3 inside Schedule-2 region → `schedule:2/para:3`, `parentKey = "schedule:2"`, `displayLabel = "paragraph 3 of Schedule 2"`.
   - Recital `(B)` → `recital:B`; `Part II` → `part:II` (roman normalised).
5. **`displayLabel`** generated from the same parts using the *configured* unit noun (per [Terminology](../CONVENTIONS.md#terminology)) so replacements read in house style.
6. **Insert** into `byKey[key]` (array push) and `ordered`.

> **Why `listString` is load-bearing:** even for fully auto-numbered documents where the visible "4.2.1" exists only in the rendering layer (the paragraph text has no digits), `listString` gives the exact rendered token. Without it we could only index static numbers and would miss every properly-authored clause.

### 4.4 Number normalisation rules

| Rendered form | Normalised `rawNumber` | Key fragment | Notes |
| --- | --- | --- | --- |
| `4`, `4.2`, `4.2.1` | unchanged | `clause:4.2.1` | Decimal body numbering. |
| `(a)`, `(b)` … | `(a)` (parens kept) | suffix `(b)` | Lettered sub-clauses. Lowercase canonical. |
| `(i)`, `(ii)`, `(iii)` (roman) | lowercase roman `(i)` | suffix `(i)` | **Roman vs letter ambiguity:** `(i)`,`(v)`,`(x)` are valid as both romans and single letters. Disambiguate by **sequence position within the parent list** (siblings from the Document Model): a roman sequence `(i),(ii),(iii)` ⇒ roman; an alphabetic sequence `(g),(h),(i)` ⇒ letter "i". Store the chosen interpretation; record `ambiguousRomanLetter: true` when both readings are plausible so the matcher can accept either. |
| Recital `(A)`,`(B)` / `A.`,`B.` | uppercase letter `A` | `recital:B` | Recitals uppercase. |
| `Part I/II/III`, roman | uppercase roman `II` | `part:II` | Parts (LMA/finance docs) often roman. |
| Annex/Appendix `A`,`B` or `1`,`2` | as-rendered, uppercase letters | `annex:A` | Lettered or numeric per house style. |

Normalisation is **symmetric**: the reference matcher (5.1.3) normalises the *cited* number with the same routine, so "Clause 4.2.1", "clause 4.2.1", and a REF field result all collapse to `clause:4.2.1`.

## 5. Algorithm

### 5.1 Feature A — Cross-Reference Checker

#### 5.1.1 Build the index
Call the builder (Clause 4) over the Document Model's single pass. Cache `SectionIndex`. Invalidate on document change (debounced) or explicit re-run.

#### 5.1.2 Scan prose for references
For each body paragraph descriptor (excluding excluded styles per Clause 8 — TOC, headers/footers not in body), run the **reference regex library** (Clause 6) over `paragraph.text`. Each hit yields a candidate `ReferenceMatch` with `rawText`, `unitType`, captured number(s), and any range/compound structure.

- Establish each hit's `range` by re-locating the literal `rawText` within the paragraph via `range.search` scoped to the paragraph (match strings are short, within the 255-char limit) or by offset mapping if the Document Model exposes character offsets. Store the `Range` for highlight + replacement.
- **Self-reference guard:** discard hits whose `rawText` is a demonstrative self-reference ("this Agreement", "this Deed", "this Clause", "this Schedule"; config list — Clause 6.7).

#### 5.1.3 Normalise & resolve
1. Normalise cited number(s) with the **same** routine as 4.4 → `normalizedKey` (and `expandedKeys` for ranges).
2. For compound refs ("paragraph 3 of Schedule 2"), build `schedule:2/para:3`. The *outer* unit (Schedule 2) must exist **and** the inner paragraph must exist within it — validate both.
3. `index.resolve(key)`: `[]` → **Not Found** (but see externalMaybe, 5.1.6); `[one]` → **OK**; `[many]` → **Ambiguous** (attach `candidateTargets`).
4. **Ambiguity from implied-parent:** if cited key is `clause:5` and the index has `clause:5(a)`, `clause:5(b)` but **no** standalone `clause:5`, resolve to those children ⇒ **Ambiguous** (cite under-specified), detected by a *prefix* lookup in `byKey` when the exact key is absent.

#### 5.1.4 REF-field detection & the static-reference badge
For each `ReferenceMatch`:
- Enumerate the host paragraph's `fields`; parse `field.code`. A code beginning `REF ` or `PAGEREF ` (case-insensitive) denotes a live cross-reference; its target bookmark is the token after `REF`.
- If the field's `range` overlaps the match `range` → `isFieldBacked = true`, `staticBadge = false`. Optionally cross-check `field.result` against `rawText`.
- Resolve the REF target bookmark against `context.document.bookmarks` and the entry's `bookmarkNames` to confirm it points at a real unit (a REF field can be broken — "Error! Reference source not found").
- If no overlapping REF/PAGEREF field → `isFieldBacked = false`, `staticBadge = true`, severity **low**, message **"manually typed — may be out of date"**.

> The static badge is **orthogonal** to OK/NotFound/Ambiguous: an OK reference can still carry the static badge (it currently resolves, but Word will not maintain it).

#### 5.1.5 Range & compound expansion
- "Schedules 2 and 3" → `expandedKeys = [schedule:2, schedule:3]`; classify each independently; the Finding lists per-target results.
- "Schedules 2 to 5 (inclusive)" → expand `[2,3,4,5]`; "(inclusive)" is consumed and ignored. Lettered endpoints expand alphabetically.
- "Clauses 4.2 and 4.3" → two clause keys.

#### 5.1.6 External / cross-document handling
If a Schedule/Annex/Appendix/Exhibit reference's outer unit is **absent** and (config heuristic) the document references attached/separate material, emit `externalMaybe` (info): "Schedule N may be in a separate file — not resolved." Never attempt to open or resolve sibling files (Office JS cannot).

#### 5.1.7 Output
One `Finding` per non-OK `ReferenceMatch` (Not Found = medium/high, Ambiguous = medium, externalMaybe = info, static badge = low). OK references with a static badge emit a low-severity badge Finding only. OK + field-backed references emit nothing (or an optional silent "passed" count).

### 5.2 Feature B — Static numbering detection (three-layer heuristic)

Run per body paragraph (same Document Model pass). Excluded styles (TOC, captions, headers/footers) are skipped (Clause 8).

#### 5.2.1 Layer (a) — pattern match on text
Match `paragraph.getText()` against **static-numbering regexes** (leading token only):
```
^\s*(\d+(\.\d+)*)[.)\t ]      // "4", "4.2", "4.2.1" then . ) tab or space
^\s*\(?([a-z])\)[ \t]         // "(a)" / "a)"
^\s*\(?((?:i|ii|iii|iv|v|vi|vii|viii|ix|x|xi|xii)+)\)[ \t]   // roman
^\s*\(?([A-Z])\)[ \t]         // recital "(A)"
```
No leading numbering pattern → `verdict = 'noNumber'`, stop.

#### 5.2.2 Layer (b) — list-membership check
Inspect `paragraph.listItem` (via `getOrNullObject`):
- **Has a `listItem`** (and non-empty `listString`) → rendered by the list engine ⇒ **dynamic**. If layer (a) *also* found a leading token, that is a *duplicate hand-typed number on top of* a list (rare but real) → flag **static/medium** ("manually typed number duplicates the automatic number"). Otherwise `verdict = 'dynamic'`, emit nothing.
- **No `listItem`** but layer (a) matched → **almost certainly static** ⇒ `verdict = 'static'`, confidence **high**, severity **low** (or **medium** if it carries a Heading style — Clause 8).

For most documents, layers (a)+(b) decide. Layer (c) runs **only** for residual ambiguous cases.

#### 5.2.3 Layer (c) — OOXML content-type inspection (only when needed)
For paragraphs where (a)+(b) are inconclusive (a field-driven number that isn't a `listItem`, or a number inside a field/SDT), call `paragraph.getOoxml()` and inspect leading content:
- Leading number is a `<w:t>` run with **no** `<w:numPr>` and **no** field (`<w:fldSimple>`/`<w:instrText>`) wrapping it → **static** (`ooxmlVerdict = 'tRun'`).
- Leading number originates from `<w:numPr>` (list) or a field element → **dynamic** (`ooxmlVerdict = 'listOrField'`).
- Mixed → `'mixed'`, verdict `indeterminate`, confidence **medium**, severity **low**.

`getOoxml()` is expensive; gate it behind the residual set and cap OOXML calls per run (config `staticNumbering.maxOoxmlProbes`, default 200) to keep large documents responsive.

#### 5.2.4 Cross-population into the Section Index
Every `verdict = 'static'` paragraph that is also a numbered unit sets `isStaticNumbered = true` on its `SectionIndexEntry`. This (a) prevents Feature A false "Not Found"s for statically-numbered units and (b) lets the UI optionally annotate a unit as "this clause's number is manually typed".

#### 5.2.5 Output
One `Finding` per `static`/`indeterminate` paragraph, `featureId = 'staticNumbering'`, `subType = 'staticNumbering'`, severity low (medium for headings or duplicate-on-list), with `goTo` navigation. **No conversion action is offered.**

### 5.3 Feature-local data models

```ts
type RefClass = 'ok' | 'notFound' | 'ambiguous' | 'externalMaybe';

interface ReferenceMatch {
  matchId: string;
  rawText: string;             // exact matched prose, e.g. "Clause 4.2", "paragraph 3 of Schedule 2"
  range: Word.Range;           // matched text range (highlight + replacement)
  paragraphId: string;
  unitType: UnitType;
  normalizedKey: string;       // e.g. "clause:4.2" — resolved against the index
  expandedKeys: string[];      // e.g. "Schedules 2 to 5" ⇒ [schedule:2..schedule:5]
  classification: RefClass;
  candidateTargets: SectionIndexEntry[]; // Ambiguous: the >1 matches; picker seeding
  isFieldBacked: boolean;      // true ⇒ backed by a REF/PAGEREF field
  fieldId?: string;
  staticBadge: boolean;        // !isFieldBacked ⇒ "manually typed — may be out of date"
  severity: Severity;
}

type NumberingVerdict = 'dynamic' | 'static' | 'noNumber' | 'indeterminate';

interface StaticNumberingResult {
  paragraphId: string;
  range: Word.Range;
  leadingNumberText: string | null;  // matched leading token, e.g. "4.2"
  hasListItem: boolean;              // layer (b)
  listStringIfAny: string | null;
  ooxmlVerdict?: 'tRun' | 'listOrField' | 'mixed'; // layer (c), only if needed
  verdict: NumberingVerdict;
  confidence: 'high' | 'medium';
  severity: Severity;                // 'low' | 'medium'
}
```

The emitted [Finding](../ARCHITECTURE.md#findings-model) carries `featureId: 'xref' | 'staticNumbering'` — the hard separator preventing Feature A and B findings from being merged or grouped (Clause 8.4) — plus `subType` (`'notFound' | 'ambiguous' | 'staticRefBadge' | 'externalMaybe'` for A; `'staticNumbering'` for B) and `payload: ReferenceMatch | StaticNumberingResult`.

## 6. Reference regex library

> All unit nouns, recital styles, and connectors come from [Terminology](../CONVENTIONS.md#terminology) and [Numbering presets](../CONVENTIONS.md#numbering-presets) (Clause 7). The patterns below show the **SG/UK default vocabulary**; the engine compiles them from config so house-style overrides are possible. **"Section" is recognised but is NOT the default unit** — do not hardcode it as primary.

Conventions: `\b` boundaries; case-insensitive except where capitalisation is semantic (Recital letters); `NUM = \d+(?:\.\d+)*`; `SUB = (?:\([a-z]+\)|\([ivxlcdm]+\))+`; `RANGE = (?:to|–|—|-)`; `LIST = (?:,|and|&)`.

### 6.1 Clause (default body unit)
```
\b(?:Clause|Cl\.?|Section|Sec\.?|§)\s+
   (NUM SUB?)                              // "Clause 4.2", "Clause 5(b)", "Clause 4.2(b)(i)"
```
- Capture full compound `4.2(b)(i)` in one group; normalise to `clause:4.2(b)(i)`.
- "Section" recognised (UK statutes; LMA top-level divisions) but classified by config: a "Section N" with a decimal child maps to the clause space unless `xref.section.isTopLevelDivision = true`.

### 6.2 Schedule (default annexure unit; recognise Exhibit but rare)
```
\b(?:Schedule|Sch\.?|Exhibit|Exh\.?)\s+
   (NUM|[A-Z])                             // "Schedule 2", "Schedule A", "Exhibit B"
```

### 6.3 paragraph-of-Schedule (compound — MUST validate both halves)
```
\bparagraph\s+(NUM SUB?)\s+of\s+
   (?:Schedule|Annex|Appendix)\s+(NUM|[A-Z])
```
- Lowercase "paragraph" is the SG/UK sub-unit *inside* schedules. Build `schedule:2/para:3`; validate Schedule 2 exists **and** paragraph 3 within it. Also handle "paragraph 3 of that Schedule" (resolve "that Schedule" to the nearest enclosing/last-named Schedule) and bare "paragraph 3" *while inside a Schedule region* (resolve against the current context-stack Schedule).

### 6.4 Annex / Appendix / Part
```
\b(?:Annex(?:ure)?|Appendix|App\.?|Part)\s+(NUM|[A-Z]|[IVXLC]+)
```
- "Part II", "Annex A", "Appendix 3".

### 6.5 Recitals / Background
```
\bRecital\s+\(?([A-Z])\)?                   // "Recital (B)", "Recital B"
|\bparagraph\s+\(?([A-Z])\)?\s+of\s+the\s+(?:Recitals|Background)
|(?<=\(\s*)([A-Z])(?=\s*\))\s             // bare "(B)" lettered recital cross-ref (context-gated)
```
- Bare `(B)` only treated as a recital reference when the index has `recital:B` and context (config) permits — otherwise ignored to avoid matching list letters.

### 6.6 Ranges & lists (apply on top of 6.1–6.5)
```
PLURAL_UNIT\s+(TOKEN)(?:\s*LIST\s*(TOKEN))+               // "Schedules 2 and 3"
PLURAL_UNIT\s+(TOKEN)\s*RANGE\s*(TOKEN)(?:\s*\(inclusive\))?  // "Schedules 2 to 5 (inclusive)"
```
- `PLURAL_UNIT` = the configured plural ("Clauses", "Schedules", "paragraphs", "Annexes", "Appendices", "Parts"). Expand to `expandedKeys` (5.1.5). `(inclusive)` consumed and ignored.

### 6.7 Self-reference exclusions (never matched as cross-refs)
Config list (`xref.selfReferenceTerms`), default: `this Agreement`, `this Deed`, `this Clause`, `this Schedule`, `this Annex`, `this Appendix`, `this Part`, `this paragraph`, `the foregoing`, `hereof`, `herein`, `hereunder`. The scanner ignores any hit whose token is a demonstrative self-reference rather than a numbered citation.

```jsonc
}
```

Hard rules (per [Terminology](../CONVENTIONS.md#terminology)): default unit is **"Clause"** ("Section" recognised via `bodyAliases`, top-level only when `xref.section.isTopLevelDivision = true`); default annexure is **"Schedule"** ("Exhibit" recognised but never offered as default replacement); inside a Schedule/Annex/Appendix the sub-unit is **"paragraph"** (lowercase, used in matching and generated `displayLabel`s); recitals are lettered uppercase `(A)/(B)/(C)` with "Background" an accepted synonym.

## 8. UI / task-pane behaviour (Proof tab)

### 8.1 Layout
Two **separate, clearly labelled groups** that never interleave:
- **"Cross-references"** (Feature A) — sub-grouped by `subType`: 1) **Broken (Not Found)** medium/high; 2) **Ambiguous** medium; 3) **May be in a separate file** info; 4) **Manually typed reference (may be out of date)** low (the static-reference *badge* list).
- **"Manually-typed clause numbers"** (Feature B).

Each group shows a count badge and is collapsible.

### 8.2 Finding row
Each row shows: `rawText` (or paragraph snippet for Feature B), severity chip, host-unit label ("in Clause 7.3"), and actions. Clicking **Go to** scrolls/selects the `Range`.

### 8.3 Assign-source picker (Feature A repair workflow)
For a Not Found or Ambiguous reference:
1. User clicks **"Assign source"**.
2. A searchable list of `SectionIndex.ordered` entries appears (filtered by compatible `unitType` first, then all). For **Ambiguous**, the `candidateTargets` are pre-surfaced at the top.
3. Each option shows `displayLabel` + a context snippet; clicking previews the replacement.
4. On confirm, the engine **replaces the matched `Range`'s text** with the target's `displayLabel` in the document's existing reference style (v1 = **static text replacement only**, via `range.insertText(label, 'Replace')`), using the **configured** unit noun (never "Section"/"Exhibit" unless config dictates).
5. Re-run resolution on the edited range; the finding clears if it now resolves uniquely.
6. **CUT in v1:** inserting a live REF field. Architectural seam (`replaceStrategy: 'text' | 'refField'`) left so v2 can add field insertion + bookmark creation.

If tracked changes is ON, the replacement is recorded as a tracked edit (no special handling beyond honouring the document's current mode).

### 8.4 Feature B presentation (kept distinct)
The "Manually-typed clause numbers" group shows per-paragraph findings with: paragraph snippet, the detected leading token ("starts with '4.2'"), a plain-language explanation ("This number was typed by hand, not generated by Word's list — it won't renumber automatically"), severity chip, and **Go to**. **No "fix"/"convert" action.** Copy must never imply automatic conversion, and these rows must never be merged with Feature A's "manually typed reference" rows — they describe a different object (a clause's own number vs a pointer to a clause). The `featureId` discriminator (5.3) enforces this at the data layer.

## 9. Edge cases

| Case | Handling |
| --- | --- |
| **Nested refs "4.2(b)(i)"** | Single compound key `clause:4.2(b)(i)`; built by walking list levels (4.3) and matched by `NUM SUB?` (6.1). |
| **List numbering resets** (a second "1." list later) | The index keys by *rendered* `listString` + context stack; if two units genuinely render the same key, `byKey[key].length > 1` ⇒ references are **Ambiguous** (correct). |
| **Heading-style inconsistency** (manually numbered non-heading paragraph) | Feature B catches it (no `listItem` + leading number). If it also looks like a heading by content, severity escalates to `staticNumbering.headingSeverity` (medium). Still indexed (with `isStaticNumbered`). |
| **TOC entries duplicating headings** | Excluded by style: paragraphs whose `style`/`styleBuiltIn` is in `xref.styles.tocStyles` are skipped for **both** index-building and reference-scanning. |
| **Content in text boxes / headers / footers** | `body.paragraphs` does **not** include them. v1 documents this blind spot (Clause 10); references and numbers there are **not** checked. |
| **Tracked-changes state** | Read tracked-changes mode. By default classify against the **final (accepted) view** so deleted-but-tracked clauses don't generate phantom targets/refs; expose a config toggle for the original view. Replacements honour the current mode. |
| **Roman-numeral ambiguity** (`(i)`,`(v)`,`(x)`) | Disambiguated by sibling sequence (4.4). When both readings are plausible, store `ambiguousRomanLetter` and let the matcher accept either. |
| **Bare "(B)" recitals** | Only matched when a `recital:B` entry exists and context permits (6.5) — avoids matching ordinary list letters. |
| **"that Schedule" / bare "paragraph N" inside a Schedule** | Resolved against the context stack's current enclosing Schedule (4.3, 6.3). |
| **REF field that is itself broken** ("Error! Reference source not found") | Detected when a REF field's target bookmark is absent from `context.document.bookmarks`; emit a Not Found finding (field-backed but broken) — higher confidence than a static Not Found. |
| **Static-numbered unit referenced by prose** | Because static units are still indexed (4.3 step 2 / 5.2.4), the reference resolves OK; no false Not Found. |
| **`search()` 255-char limit** | Never used for compound/long queries; match strings are short tokens. Primary scan is regex over loaded paragraph text — see [Office JS constraints reference](../ARCHITECTURE.md#office-js-constraints-reference) row 8. |

## 10. Known limitations

1. **No true staleness detection.** ❌ We cannot tell that "Clause 4.2" *used to* mean something else after a renumber — only that it currently resolves, is ambiguous, or is broken. The static-reference badge is a proxy ("Word won't auto-maintain this"), not proof of staleness.
2. **Static text replacement only** in Assign-source (no live REF field in v1). ❌ Repaired references remain manually-typed and will drift again on renumber. (v2 seam present.)
3. **No cross-document resolution.** ❌ Schedules/exhibits in sibling files are flagged "may be in a separate file" and never resolved — Office JS cannot read other files.
4. **Blind to text boxes, headers, footers, footnotes/endnotes** — `body.paragraphs` excludes them; references and numbering there are unchecked.
5. **Feature B is detect-only.** ❌ No conversion of static numbering to dynamic lists; the user fixes it manually.
6. **Roman/letter ambiguity** is resolved heuristically by sibling sequence; pathological mixed lists may mis-classify a single `(i)`/`(v)`/`(x)`; we accept either reading to avoid false Not Found, at the cost of occasionally over-accepting.
7. **OOXML probing is capped** (config) for performance; beyond the cap, residual ambiguous paragraphs are reported as `indeterminate` (low severity) rather than probed.

### 12.3 Cross-cutting acceptance
- Feature A and Feature B findings appear in **separate** task-pane groups; no row from one appears under the other (assert on `featureId`).
- Statically-numbered units (Feature B `static`) are present in the Section Index (`isStaticNumbered=true`) and do **not** cause false Not Found in Feature A (cross-check B2's unit referenced elsewhere → OK).
- No replacement is ever offered for Feature B findings.
- Default replacement labels never emit "Section"/"Exhibit" unless config overrides.
